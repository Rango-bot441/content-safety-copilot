# Content Safety Copilot

Content Safety Copilot 是一个面向抖音创作者的发布前内容安全辅助工具。它帮助创作者在发布视频前检查标题、口播稿、正文内容和评论区互动引导中的潜在风险，并提供更稳妥的表达改写建议与发布前自查清单。

项目当前版本是一个纯前端原型，重点展示内容安全场景中的产品机制设计：从内容送检、风险识别、风险分级、表达改写，到发布前自查，形成一个轻量但完整的审核辅助闭环。

## 解决的问题

创作者在内容发布前经常会遇到几个问题：

- 表达过于绝对，例如“保证”“一定”“稳赚”等，容易造成误导预期。
- 评论区引导过于机械，例如“评论区打 1”“点赞领取”，影响内容体验。
- 财经、健康、就业、教育等垂类容易涉及敏感表达，需要补充边界说明。
- 创作者知道内容需要“更合规”，但不知道具体应该改哪里、怎么改。
- 平台侧如果只给出“存在风险”的结论，创作者很难形成可执行的修改动作。

Content Safety Copilot 希望把抽象的内容安全要求转化成更明确的产品流程：识别风险点、解释原因、给出改写方向，并帮助创作者在发布前完成最后一轮自查。

## 目标用户

| 用户类型 | 典型需求 |
| --- | --- |
| 抖音创作者 | 发布前检查标题、口播稿、评论引导是否存在风险表达 |
| 内容运营人员 | 快速定位内容中的风险点，并给出修改建议 |
| MCN / 内容团队 | 用统一规则辅助批量内容初筛，降低人工沟通成本 |
| 平台工具设计者 | 验证“内容安全 + 表达改写 + 自查清单”的产品机制 |

## 核心业务洞察

内容安全工具不应该只告诉用户“有风险”，更应该回答三个问题：

1. 风险在哪里：明确指出命中的风险类型和具体表达。
2. 为什么有风险：用创作者能理解的方式解释风险原因。
3. 应该怎么改：给出保留原意、降低误导、减少诱导互动的改写方案。

因此，本项目没有把内容安全做成单一审核结论，而是设计成一个“发布前协作流程”。创作者可以先输入内容，系统给出风险概览，再逐条查看风险解释，最后复制修改后的完整文案继续发布。

## 产品机制设计

项目采用“规则初筛 + 风险分级 + 改写建议 + 自查清单”的机制。

### 1. 内容送检

用户输入或选择：

- 内容垂类
- 账号粉丝量区间
- 视频标题 / 封面文案
- 口播稿 / 正文内容
- 评论区互动引导

### 2. 风险识别

系统基于内置规则表检测以下风险类型：

| 风险类型 | 示例表达 |
| --- | --- |
| 夸大承诺 | 一定、保证、包过、必火 |
| 诱导互动 | 评论区打 1、点赞领取、关注后发 |
| 敏感资料暗示 | 内部资料、内部渠道、独家内幕 |
| 泛化绝对判断 | 所有人、唯一方法、彻底解决 |
| 财经金融敏感 | 稳赚、翻倍、无风险收益 |
| 健康医疗敏感 | 根治、药到病除、不用去医院 |
| 引战表达 | 攻击性、对立式、侮辱性措辞 |

### 3. 风险分级与可发布分

检测结果以四宫格集中展示：

- 风险等级
- 命中风险点数量
- 可发布分
- 重点关注类型

当前版本的可发布分采用简化规则：

```text
可发布分 = 96 - 高风险命中数 × 24 - 中风险命中数 × 12
```

分数不是平台真实评分，只用于表达“风险越多，发布前越需要修改”的产品逻辑。

### 4. 表达改写

系统会展示“修改前 vs 修改后”的对照视图，并高亮具体改动。用户可以一键复制修改后的完整文案。

改写原则包括：

- 把确定性承诺改为经验型、概率型表达。
- 把机械诱导互动改为自然提问。
- 把“内部资料”等敏感暗示改成“公开资料整理清单”。
- 给敏感垂类补充适用条件与边界说明。

### 5. 发布前自查

自查清单用于帮助创作者在发布前再次确认：

- 是否避免确定性承诺。
- 是否说明适用人群。
- 评论引导是否自然。
- 敏感内容是否补充边界说明。
- 修改后是否仍保留内容吸引力。

## 核心功能模块

| 模块 | 说明 |
| --- | --- |
| 内容送检 | 输入内容垂类、账号粉丝量、标题、正文和评论引导 |
| AI 检测结果 | 展示风险等级、命中数量、可发布分和重点关注 |
| 运营判断 | 用自然语言总结当前内容的主要问题和处理优先级 |
| 命中风险点 | 列出风险类型、原因和对应修改建议 |
| 表达改写建议 | 对比修改前后文案，并高亮改动部分 |
| 一键复制 | 复制修改后的标题、正文和评论引导全文 |
| 发布前自查清单 | 提供发布前最后一轮检查项 |
| 样例切换 | 内置多个不同垂类的示例，方便快速体验 |

## 技术实现方式

当前项目为纯静态单页应用，不依赖构建工具。

```text
content-safety-copilot/
├── index.html       # 页面结构、样式和交互逻辑
├── README.md        # 项目说明
├── .gitignore       # Git 忽略配置
└── .env.example     # 环境变量示例
```

技术组成：

- HTML：页面结构与表单输入。
- CSS：响应式布局、卡片、风险状态、改写对比和高亮样式。
- JavaScript：规则检测、风险分级、文案改写、复制、样例切换。

当前版本不会调用外部模型 API，也不会上传用户输入内容。所有检测逻辑都在浏览器本地完成。

## 本地运行

### 方式一：直接打开文件

直接用浏览器打开：

```text
index.html
```

### 方式二：启动本地静态服务

在项目目录运行：

```bash
python3 -m http.server 4182
```

然后访问：

```text
http://localhost:4182/index.html
```

如果使用 Node.js，也可以运行：

```bash
npx serve .
```

## 部署到公网

这是一个纯静态项目，可以部署到任意静态托管平台。

### GitHub Pages

1. 将项目推送到 GitHub 仓库。
2. 进入仓库 Settings。
3. 打开 Pages。
4. Source 选择 `Deploy from a branch`。
5. 选择主分支和项目根目录。
6. 保存后等待 GitHub Pages 生成访问链接。

### Vercel

1. 在 Vercel 导入 GitHub 仓库。
2. Framework Preset 选择 `Other`。
3. Build Command 留空。
4. Output Directory 留空或使用默认根目录。
5. 部署完成后访问生成的公网地址。

### Netlify

1. 在 Netlify 新建站点并导入 GitHub 仓库。
2. Build Command 留空。
3. Publish Directory 设置为项目根目录。
4. 部署完成后访问生成的公网地址。


## 当前版本边界

- 当前检测结果来自内置规则，不代表平台真实审核结果。
- 当前改写基于关键词替换，不具备完整语义理解能力。
- 不支持账号登录、历史记录、多用户协作或云端存储。
- 不会调用外部模型 API，也不会自动同步真实平台规则。
- 可发布分是产品演示指标，不是实际内容分发或审核评分。
- 对图片、视频画面、音频语气等多模态风险暂未覆盖。

## 后续迭代方向

- 接入大模型复核：在规则初筛后，引入模型进行语义级风险解释和更自然的改写。
- 增加垂类规则库：针对财经、医疗、教育、本地生活等高敏垂类建立更细的规则。
- 支持多模态检测：增加封面图、视频截图、字幕文件和音频转写的风险识别。
- 引入版本对比：保存多轮改写记录，帮助用户理解每次修改的变化。
- 增加团队协作：支持运营人员批注、审核状态流转和内容批量处理。
- 建立效果反馈：记录发布后互动、申诉、举报等反馈，用于优化风险规则。
- 支持后端服务：将规则、样例、模型配置和检测记录拆分到服务端，便于持续维护。

## 安全说明

- 不要提交 `.env`、真实 API Key、访问令牌或任何个人敏感信息。
- 如需接入外部模型，应在服务端代理请求，避免将密钥暴露在浏览器代码中。
- 用户输入内容在当前版本只在本地浏览器处理，不会主动发送到外部服务。
