# PRD：Content Safety Copilot

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | Content Safety Copilot |
| 当前版本 | MVP v1.0 |
| 产品类型 | 面向创作者的发布前内容安全辅助工具 |
| 目标平台 | Web 单页原型 |
| 线上地址 | https://content-safety-copilot.onrender.com |
| 核心场景 | 抖音创作者发布前检查标题、口播稿、正文和评论引导的潜在风险 |

## 2. 背景与问题

抖音创作者在发布内容前，常常需要同时兼顾内容吸引力、平台规则、用户体验和垂类合规边界。尤其在职场、财经、健康、教育等垂类中，创作者容易出现“保证、一定、稳赚、根治、内部资料”等高风险表达。

现有内容安全提示通常只告诉用户“存在风险”，但创作者真正需要的是可执行的修改动作：哪里有风险、为什么有风险、应该怎么改、改完还能不能保留原本的表达吸引力。

Content Safety Copilot 希望把抽象的平台规则转化为发布前可操作的辅助流程，帮助创作者降低违规风险，同时提升内容表达质量。

## 3. 目标用户

| 用户类型 | 典型需求 | 当前优先级 |
| --- | --- | --- |
| 抖音创作者 | 发布前快速检查内容表达风险，并获得改写建议 | P0 |
| 内容运营人员 | 帮创作者批量初筛标题、脚本、评论引导 | P1 |
| MCN / 内容团队 | 建立统一的内容发布前审核标准 | P1 |
| 平台工具设计者 | 验证“内容安全 + 表达改写 + 自查清单”的产品机制 | P2 |

## 4. 产品目标

### 4.1 用户目标

- 创作者能在发布前发现高风险表达。
- 创作者能理解风险原因，而不是只看到抽象结论。
- 创作者能直接拿到更稳妥的替代表达。
- 创作者能在不牺牲内容吸引力的前提下降低风险。

### 4.2 业务目标

- 降低创作者内容发布前的合规判断成本。
- 提升内容审核提示的可解释性和可执行性。
- 建立一个可扩展到多垂类、多模态检测的内容安全产品原型。

## 5. MVP 范围

### 5.1 本期包含

| 功能 | 描述 | 优先级 |
| --- | --- | --- |
| 内容送检 | 输入内容垂类、粉丝量、标题、口播稿、评论引导 | P0 |
| 风险识别 | 基于规则识别夸大承诺、诱导互动、敏感资料暗示等风险 | P0 |
| 风险等级 | 输出高风险、中风险、低风险 | P0 |
| 可发布分 | 用分数表达当前内容的发布风险 | P0 |
| 命中原因 | 展示风险类型、风险原因和修改建议 | P0 |
| 表达改写 | 输出修改前后对比，并高亮替换内容 | P0 |
| 一键复制 | 复制修改后的完整文案 | P1 |
| 发布前自查 | 提供最后一轮人工检查清单 | P1 |
| 样例切换 | 提供不同垂类样例，方便演示和体验 | P1 |

### 5.2 本期不包含

- 用户登录与账号体系。
- 云端保存历史检测记录。
- 真实平台审核接口接入。
- 图片、视频、音频等多模态内容检测。
- 大模型语义审核。
- 自动发布或自动拦截内容。

## 6. 核心用户流程

```text
进入页面
  → 选择内容垂类和账号粉丝量
  → 输入标题 / 封面文案
  → 输入口播稿 / 正文
  → 输入评论区互动引导
  → 点击开始安全检测
  → 查看风险等级、命中风险点、可发布分
  → 查看风险原因和修改建议
  → 对比修改前后文案
  → 复制修改后全文案
  → 按发布前自查清单人工确认
```

## 7. 功能需求

### 7.1 内容送检

用户可以输入或选择以下信息：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 内容垂类 | 下拉选择 | 是 | 用于提示不同垂类的风险语境 |
| 账号粉丝量 | 下拉选择 | 是 | 用于辅助判断账号阶段 |
| 视频标题 / 封面文案 | 文本输入 | 否 | 检测标题中的夸大、承诺、敏感词 |
| 口播稿 / 正文内容 | 多行文本 | 否 | 检测主要内容风险 |
| 评论区互动引导 | 文本输入 | 否 | 检测诱导互动风险 |

至少填写标题、正文、评论引导中的任意一项，才能执行检测。

### 7.2 风险识别

系统基于规则表扫描用户输入文本。当前风险类型包括：

| 风险类型 | 风险等级 | 示例关键词 |
| --- | --- | --- |
| 夸大承诺 | 高 | 一定、保证、必火、包过 |
| 诱导互动 | 中 | 评论区打、点赞领取、关注后发 |
| 敏感资料暗示 | 中 | 内部资料、内部渠道、独家内幕 |
| 泛化绝对判断 | 中 | 所有人、唯一方法、彻底解决 |
| 财经金融敏感 | 高 | 稳赚、翻倍、无风险收益 |
| 健康医疗敏感 | 高 | 根治、药到病除、不用去医院 |
| 引战表达 | 中 | 垃圾、活该、脑子不好 |

### 7.3 风险等级与可发布分

风险等级规则：

```text
存在高风险命中 → 高风险
不存在高风险但存在中风险命中 → 中风险
无明显命中 → 低风险
```

可发布分规则：

```text
可发布分 = 96 - 高风险命中数 × 24 - 中风险命中数 × 12
最低分 = 35
```

可发布分只用于产品演示，不代表真实平台审核结果。

### 7.4 风险解释

每个命中风险点需要展示：

- 风险类型。
- 风险等级。
- 风险原因。
- 修改建议。

示例：

```text
风险类型：夸大承诺
风险原因：表达中包含确定性承诺，容易造成误导预期。
修改建议：改成基于经验或案例的概率表达。
```

### 7.5 表达改写

系统需要展示三类内容的修改前后对比：

- 标题 / 封面文案。
- 口播稿 / 正文内容。
- 评论区互动引导。

改写原则：

- 确定性承诺改为概率型或经验型表达。
- 诱导互动改为自然讨论。
- 敏感资料暗示改为公开资料说明。
- 泛化判断补充适用范围。

### 7.6 一键复制

用户点击“复制修改后全文案”后，系统复制包含标题、正文、评论引导的完整安全版本。

复制内容格式：

```text
【标题/封面文案】
...

【口播稿/正文内容】
...

【评论区互动引导】
...
```

### 7.7 发布前自查清单

检测完成后展示自查清单：

- 是否避免确定性承诺？
- 是否说明适用人群？
- 评论引导是否自然？
- 敏感内容是否补充边界说明？
- 修改后是否保留内容吸引力？

## 8. 非功能需求

| 类型 | 要求 |
| --- | --- |
| 性能 | 本地规则检测应在 2 秒内返回结果 |
| 隐私 | 当前版本不上传用户输入内容 |
| 可用性 | 页面支持桌面与移动端基础响应式访问 |
| 可解释性 | 每个风险结果必须包含原因和修改建议 |
| 可维护性 | 后续规则库应可独立配置和扩展 |

## 9. 风险与边界

- 当前版本是规则模拟，不代表抖音真实审核策略。
- 当前改写是关键词替换，不具备完整语义理解能力。
- 可发布分是演示指标，不能承诺内容一定通过审核。
- 不能替代人工审核，尤其是财经、医疗、法律等高敏垂类。
- 如果后续接入大模型，需要通过服务端代理，避免 API Key 暴露。

## 10. 验收标准

| 场景 | 验收标准 |
| --- | --- |
| 空输入检测 | 提示用户先输入内容 |
| 高风险内容 | 能输出高风险等级、命中点和改写建议 |
| 中风险内容 | 能输出中风险等级并解释互动或资料风险 |
| 低风险内容 | 能提示整体稳妥，并建议人工复核 |
| 改写对比 | 修改前后内容清晰可见，变更内容有高亮 |
| 复制全文案 | 点击后可复制修改后的完整文案 |
| 移动端访问 | 页面布局不出现严重遮挡或横向溢出 |
