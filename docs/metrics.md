# 指标体系：Content Safety Copilot

## 1. 指标设计目标

Content Safety Copilot 当前是可交互原型，但仍需要具备清晰的数据评估意识：这个工具上线后，如何判断它是否真的帮创作者降低风险、提升效率、改善体验。

指标设计围绕三个问题：

- 用户有没有用？
- 检测和改写有没有帮助？
- 是否能降低发布前风险？

## 2. 北极星指标

| 指标 | 定义 | 选择原因 |
| --- | --- | --- |
| 有效改写采纳率 | 用户完成检测后，复制或采用修改后文案的比例 | 直接反映工具是否把风险提示转化成可执行修改 |

计算方式：

```text
有效改写采纳率 = 复制修改后全文案的检测次数 / 完成检测次数
```

## 3. 核心漏斗指标

```text
访问页面
  → 输入内容
  → 点击安全检测
  → 查看风险结果
  → 查看改写建议
  → 复制修改后文案
  → 完成发布前自查
```

| 漏斗环节 | 指标 | 说明 |
| --- | --- | --- |
| 访问 | 页面访问量 | 衡量入口吸引力 |
| 输入 | 内容输入率 | 用户是否愿意开始使用 |
| 检测 | 检测触发率 | 表单和按钮是否清晰 |
| 结果 | 结果查看率 | 用户是否等待结果生成 |
| 改写 | 改写区域查看率 | 改写建议是否被关注 |
| 采纳 | 复制率 | 改写内容是否可用 |
| 自查 | 自查完成率 | 用户是否形成发布前确认动作 |

## 4. 功能效果指标

| 指标 | 定义 | 目标方向 |
| --- | --- | --- |
| 风险命中率 | 检测中至少命中 1 个风险点的比例 | 用于判断规则覆盖情况 |
| 高风险占比 | 高风险检测次数 / 总检测次数 | 用于识别高敏内容比例 |
| 平均可发布分 | 所有检测结果的平均分 | 观察用户内容风险整体变化 |
| 二次检测率 | 同一用户短时间内重新检测的比例 | 反映用户是否根据建议修改 |
| 分数提升率 | 二次检测后分数高于首次检测的比例 | 反映建议是否有效 |
| 改写采纳率 | 用户复制或手动采用改写结果的比例 | 衡量改写质量 |

## 5. 用户体验指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 检测完成时间 | 从点击检测到结果展示的时间 | MVP 控制在 2 秒内 |
| 空输入错误率 | 用户未输入内容就点击检测的比例 | 越低越好 |
| 复制失败率 | 用户点击复制但复制失败的比例 | 越低越好 |
| 移动端完成率 | 移动端完成检测的比例 | 不低于桌面端明显水平 |
| 用户满意度 | 用户对风险解释和改写建议的评分 | 持续提升 |

## 6. 内容安全效果指标

这些指标需要真实发布链路或人工标注后才能完整验证：

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 人工复核通过率 | 经工具修改后的内容通过人工复核的比例 | 衡量工具辅助质量 |
| 发布后申诉率 | 内容发布后被处罚并申诉的比例 | 观察误伤或误导风险 |
| 举报率 | 发布后被用户举报的比例 | 衡量社区体验风险 |
| 违规召回率 | 工具命中的真实违规内容 / 所有真实违规内容 | 衡量风险识别覆盖 |
| 误判率 | 被工具标记但人工认为无风险的比例 | 衡量规则过严程度 |

## 7. 埋点方案

| 事件名 | 触发时机 | 关键属性 |
| --- | --- | --- |
| page_view | 用户打开页面 | device_type、source |
| content_input_started | 用户开始输入内容 | field_name、vertical |
| sample_loaded | 用户点击样例 | sample_vertical |
| scan_clicked | 用户点击开始检测 | vertical、fan_range、text_length |
| scan_completed | 检测完成 | risk_level、issue_count、score |
| issue_viewed | 用户查看风险点 | issue_type、risk_level |
| rewrite_viewed | 用户查看改写建议 | changed_field_count |
| safe_copy_clicked | 用户点击复制全文案 | risk_level、score |
| checklist_viewed | 用户查看自查清单 | risk_level |
| empty_input_prompted | 空输入检测 | current_field_state |

## 8. 目标值建议

| 阶段 | 目标 |
| --- | --- |
| 原型验证期 | 重点看用户是否理解流程，检测触发率 > 40% |
| MVP 试用期 | 改写采纳率 > 25%，二次检测率 > 15% |
| 小范围上线期 | 分数提升率 > 40%，复制失败率 < 2% |
| 规则优化期 | 通过人工标注持续降低误判率 |

## 9. 数据驱动迭代方式

```text
收集检测结果
  → 分析高频风险类型
  → 找出用户最常复制的改写建议
  → 观察二次检测后的分数变化
  → 优化规则库和改写策略
  → 在高敏垂类中增加专属规则
```

## 10. 当前原型限制

- 当前版本没有真实埋点，只在文档中定义指标方案。
- 当前无登录体系，无法稳定识别用户级漏斗。
- 当前没有真实发布后数据，无法验证举报率、申诉率等后验指标。
- 当前规则命中不代表真实平台审核策略。
